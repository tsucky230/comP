v0.12.0 — マルチルートのワークスペースに対応

AI に、リポジトリの
地図を持たせる。

comP（コンプ）は、リポジトリのファイル・関数・呼び出し関係を手元で索引にして、Claude Code や Codex、Cursor などの AI コーディングエージェントに渡す VS Code 拡張です。作業の最初に comP に聞けば、AI はどこに何があり、何が何に依存しているかを一度でつかめます。オープンソースで、索引も作業の記録も手元のマシンに残ります。

使ってみる GitHubで見る

作ったきっかけは、トークン代でした

最初の目的は単純で、AI に読ませるトークンを減らすことでした。Claude Code に小さな修正を頼むたびに、AI は grep を何度も打ち、関係のないファイルまで開いて、ようやく本題にたどり着きます。その探索に毎回お金と待ち時間を払うのが、もったいなく感じていました。

そこで、リポジトリを一度だけ索引にしておき、作業の内容を伝えると関係のあるファイルとシンボル（関数やクラスの名前）だけを返す仕組みを作りました。トークンは確かに減りました。ただ、使い続けるうちに、それより大きな変化に気づきました。AI の仕事の質が変わったのです。

地図を持った AI は、最初から正しいファイルを開き、関数を変える前に呼び出し元を確かめ、前回のセッションで決めたことを踏まえて続きを始めることが増えました。目の前のファイルだけを見ていた視野が、リポジトリ全体に広がった感覚です。私は、この変化が comP のいちばんの価値だと考えています。

地図を持った AI は仕事の質が変わる

comP は MCP（AI エージェントが外部のツールを呼ぶための共通の仕組み）のサーバーとして動きます。ふだんは、あなたが作業を頼むと、AI が自分で comP のツールを呼びます。

🧭

最初の一手で関係するファイルへ

AI がやりたい作業を一文で run_pipeline に渡すと、関係の深い順にファイルが返ります。まだコミットしていない変更があるファイルは先頭に、依存関係で一歩つながるファイルも一緒に。見当違いのファイルを読んで誤った前提で実装し、やり直す回り道が減ります。

🕸️

変える前に波及先が見える

get_impact_graph は、あるシンボルに依存している関数とファイルを、依存グラフをたどって列挙します。AI が変更の前に呼べば、確かめるべき呼び出し元とテストが分かった状態で手を入れられます。変更を重ねるたびに品質が落ちていくのを、ここで止めたいと考えています。

📓

昨日までの作業と判断を次のセッションへ

AI が run_pipeline と get_context で調べた内容は、セッションをまたいで自動で記録されます。作業の区切りに AI が session_log で依頼と結果を残せば判断まで残り、次のセッションは session_recall で続きから始められます。日本語の問いでも引けます。

🔒

データは手元から出ない

索引と記録はリポジトリの .comp/ に置きます。デーモンは外部と通信せず、拡張機能もテレメトリを送りません。例外は VS Code のチャットの @comp で、依頼文と添付ファイルの圧縮内容が、VS Code で選んでいる言語モデルへ送られます。

comP 自身の開発でも、地図に助けられています

マルチルートのワークスペースへの対応を頼んだときは、AI が最初の run_pipeline の結果から、既存の不具合に実装の前に気づきました。返ってきた daemon/src/main.rs を読み、additional_paths 機能がメインの索引を消してしまうことを見つけたのです。頼まれた場所の外にまで目が届くのは、地図があるからだと思います。

デーモン（索引を管理する常駐プロセス）を再起動しても、Claude Code から Codex に替えても、同じ記録を読めます。私の使っている範囲では、Claude や ChatGPT のメモリー機能は会話の要約や好みを覚えるのが得意で、コードの細部は要約の途中で落ちがちでした。comP の記録は、そのリポジトリでの技術的な判断に絞った索引です。覚えるものが違うので、両方を使い分けるのがおすすめです。

VS Code から始めて、エージェントは自動でつなぐ

サイドバーの Start を押すと、Rust 製のデーモンがリポジトリを索引にします。保存したコードや Markdown はその場で索引し直し、git でブランチを切り替えたときは全体を作り直します。

comP: Setup Agents は、Claude Code・Codex・Cursor・Cline・Windsurf・Continue・GitHub Copilot・Antigravity・Aider・Gemini CLI が実際に読む設定ファイルへ、既存の MCP サーバーの設定を残したまま書き込みます。手で貼り付ける作業はありません。VS Code のチャットでは @comp で、ファイルを圧縮してから LLM に渡すこともできます。

数字で見ると

効果は、リポジトリの大きさと作業の種類で大きく変わります。測った値を、条件と一緒に載せます。

📏

約44万トークンのうち、約8,000トークン

comP 自身のリポジトリで、マルチルート対応の作業に run_pipeline が返した量です（ファイル9件）。既定の予算 8,000 トークンに合わせて圧縮した量で、全体の約1.8%にあたります。AI が実際にどれだけ読むかは作業によるので、ここから出る削減率は上限と考えてください。

🗺️

145,978トークンを、289トークンの要約に

MAGATAMA のリポジトリで概要をつかむ作業1件を、MAGATAMA 側で測った値です。選んだソースを読む場合の推定と、comP の要約を比べています。一度きりの計測で、どのプロジェクトでも同じ割合になるわけではありません。

📦

小さなリポジトリでは、差は小さい

数十ファイルほどなら、全部読んでも安く済み、伸びしろは少なめです。これは計測していない見込みです。

表に出にくい効果：やり直しが減る

探索で迷った AI は、違うファイルを読み、誤った前提で実装し、テストに落ちてやり直します。この往復は、1回で数千トークン（目安）を使います。私の使っている範囲では、comP を入れてからこの往復が目に見えて減り、安いモデルほどその差が大きく出ました。

MAGATAMA と組むと変更前に確かめる場所を根拠つきで出せる

MAGATAMA（勾玉）は、comP の索引を読んで「このファイルを変えたら、どこを確認すればいいか」を答える、もう一つの MCP サーバーです。comP が地図を作り、MAGATAMA はその地図を変更前の点検に使います。

🔎

最初に読む関数はどれか

comP の run_pipeline と get_context に聞きます。

🧩

このファイルを変えたら、どこを確認するか

MAGATAMA の analyze_change_scope が、波及候補と、そこに至る依存関係を根拠として返します。

🕰️

前にこのファイルを触った理由は何か

MAGATAMA の履歴照会と、comP の session_recall で探します。

🛰️

前回から何が変わったか

MAGATAMA の patrol（留守の間の変更を確かめて次のセッションに残す機能）の記録と、comP の session_recall を読みます。

分からないときは「unknown」と答える

comP の get_impact_graph が1つのシンボルから依存元を並べるのに対し、analyze_change_scope は変更するファイルを単位に受け取り、中のシンボルすべてから依存関係を逆にたどって、波及候補ごとに影響の経路を根拠として添えます。ファイル名があいまいなときや、索引に依存関係が足りないときは、analyze_change_scope は推測で埋めずに「unknown（要確認）」と返します。私はこの正直さを気に入っています。結果は確認の出発点で、実行時の影響をすべて証明するものではありません。

analyze_change_scope はまだ PyPI の公開版に入っていないので、いまは、この機能を含む MAGATAMA のチェックアウトから使います。導入の手順は MAGATAMA の README にあります。

マルチルートのワークスペース

✅ リリース済み

使い始める

VS Code に入れて、索引を作り、エージェントにつなぐ。3つの手順です。VS Code 1.91 以降で、デーモンは Windows・macOS・Linux 用を同梱しています。

1

拡張機能を入れる

VS Code の拡張機能ビュー（Ctrl+Shift+X）で「comP - Code Context Engine」を検索して、インストールします。リリースの .vsix から入れる場合は、次のコマンドを使います。

code --install-extension comP-0.12.0.vsix
2

索引を作る

作業するリポジトリを開き、サイドバーの comP から Start を押します。索引はバックグラウンドで作られ、進み具合はステータスバーに出ます。2回目からは、変更のあったファイルだけを解析し直します。索引と作業の記録はリポジトリの .comp/ に入るので、.gitignore に .comp/* と !.comp/ignore の2行を足してください（そのままコミットすると、作業の記録や会話の本文がリモートに上がります）。

3

エージェントにつなぐ

コマンドパレットで comP: Setup Agents を実行し、使うエージェントを選びます。この PC で見つかったエージェントは最初から選ばれています。書き込んだら、エージェントを再起動してください（どのツールも、起動している間は MCP の設定を読み直しません）。書き込み先は次のとおりです。

  • Claude Code: .mcp.json（任意で claude mcp add --scope user によるユーザースコープ登録も）
  • Codex: ~/.codex/config.toml と .codex/config.toml（プロジェクト側は「信頼済みプロジェクト」でのみ有効）
  • GitHub Copilot: .vscode/mcp.json
  • Cursor: .cursor/mcp.json と ~/.cursor/mcp.json
  • Cline: VS Code のグローバルストレージにある MCP 設定
  • Windsurf: ~/.codeium/windsurf/mcp_config.json
  • Continue.dev: .continue/mcpServers/comp.yaml（プロジェクトとホーム）
  • Antigravity（App・IDE・agy CLI・VS Code 拡張）: ~/.gemini/config/mcp_config.json
  • Aider: ワークスペースルートの .aider.conf.yml
  • Gemini CLI: .gemini/settings.json と ~/.gemini/settings.json（有料の Gemini API キーか Code Assist Standard / Enterprise のライセンスがある場合のみ。個人アカウントは 2026-06-18 に提供終了）
